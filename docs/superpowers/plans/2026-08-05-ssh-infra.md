# SSH TUI Infrastructure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put the Go SSH TUI on a public AWS address with OpenTofu, and give it a GitHub Actions deploy path that uses OIDC rather than long-lived credentials.

**Architecture:** A small bootstrap config with local state creates the state bucket. The main config creates one `t4g.micro` instance with an Elastic IP, an artifact bucket, an SSM-stored host key, and an IAM role GitHub Actions federates into. `user_data` disables `sshd`, installs a hardened systemd unit, and pulls the binary. Deploys upload to S3 and trigger `ssm send-command`.

**Tech Stack:** OpenTofu 1.11.4, AWS `us-west-2`, Amazon Linux 2023 arm64, GitHub Actions.

## Global Constraints

- Spec: `docs/superpowers/specs/2026-08-05-ssh-infra-design.md`. Read it before starting.
- **Nothing in this plan runs `tofu apply`.** No task creates, modifies, or destroys a single AWS resource. `tofu init -backend=false`, `validate`, and `fmt` are the limit. The owner applies.
- **Read-only AWS calls are permitted** for verification — `sts get-caller-identity`, `ssm get-parameters` for the AMI, `iam list-open-id-connect-providers`. Nothing that mutates.
- Local credentials are `AWS_PROFILE=resume-tui` (`AdministratorAccess`). Never print a secret access key, and never write credentials into a file in the repository.
- **The account ID must not appear in any committed file.** Resolve it at apply time via `data.aws_caller_identity.current.account_id`.
- **Do not touch the website or the Go program.** No changes to `src/`, `index.html`, `vercel.json`, `package.json`, `tests/`, `prerender.ts`, `content.json`, `cmd/`, or `internal/`.
- `tofu fmt` clean. `shellcheck` clean on shell scripts. `actionlint` clean on workflows.
- One commit per task. Work on branch `infra-ssh`.

## Facts already verified — do not re-derive

- `tofu` on PATH is **v1.11.4**, and it **accepts `use_lockfile = true`** on the S3 backend, so no DynamoDB table is needed.
- The account **already has** an IAM OIDC provider for `token.actions.githubusercontent.com`. Creating another fails with `EntityAlreadyExists`. Read it with a data source.
- The AL2023 arm64 AMI resolves from SSM parameter `/aws/service/ami-amazon-linux-latest/al2023-ami-kernel-default-arm64` (currently `ami-098176c88d53db397` in us-west-2). Use the parameter, not the ID.
- The repository is `phetzy/fetzycloudonline` and it is **public**.

### Task 1: Bootstrap the state bucket config

**Files:**
- Create: `terraform/bootstrap/main.tf`, `terraform/bootstrap/README.md`
- Modify: `.gitignore`

**Interfaces:**
- Produces: a bucket named `fetzer-tfstate-${account_id}`, referenced by Task 2's backend block.

- [ ] **Step 1: Write `terraform/bootstrap/main.tf`**

Local state deliberately — this config creates the bucket the main config's backend needs, so it cannot itself live in that bucket.

```hcl
terraform {
  required_version = ">= 1.11.0"
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}

provider "aws" {
  region = var.region
}

variable "region" {
  type    = string
  default = "us-west-2"
}

data "aws_caller_identity" "current" {}

locals {
  # The account ID never appears in a committed file; it is resolved at apply
  # time. This repository is public.
  bucket_name = "fetzer-tfstate-${data.aws_caller_identity.current.account_id}"
}

resource "aws_s3_bucket" "state" {
  bucket = local.bucket_name

  # State is the one thing here that cannot be rebuilt from the repository.
  lifecycle {
    prevent_destroy = true
  }
}

resource "aws_s3_bucket_versioning" "state" {
  bucket = aws_s3_bucket.state.id
  versioning_configuration {
    status = "Enabled"
  }
}

resource "aws_s3_bucket_server_side_encryption_configuration" "state" {
  bucket = aws_s3_bucket.state.id
  rule {
    apply_server_side_encryption_by_default {
      sse_algorithm = "AES256"
    }
  }
}

resource "aws_s3_bucket_public_access_block" "state" {
  bucket                  = aws_s3_bucket.state.id
  block_public_acls       = true
  block_public_policy     = true
  ignore_public_acls      = true
  restrict_public_buckets = true
}

output "state_bucket" {
  value = aws_s3_bucket.state.id
}
```

### Task 2: Main config skeleton — providers, backend, variables

**Files:**
- Create: `terraform/main.tf`, `terraform/variables.tf`

**Interfaces:**
- Produces: `data.aws_caller_identity.current`, `data.aws_ssm_parameter.al2023_arm64`, and the variable set every later task uses.

- [ ] **Step 1: Write `terraform/main.tf`**

```hcl
terraform {
  required_version = ">= 1.11.0"

  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }

  # Native S3 locking — verified supported by the installed tofu 1.11.4, so no
  # DynamoDB table is needed. The bucket comes from terraform/bootstrap.
  backend "s3" {
    key          = "ssh-tui/terraform.tfstate"
    region       = "us-west-2"
    encrypt      = true
    use_lockfile = true
    # bucket is supplied at init time: see terraform/README.md
  }
}

provider "aws" {
  region = var.region

  default_tags {
    tags = {
      Project   = var.project
      ManagedBy = "opentofu"
      Repo      = "phetzy/fetzycloudonline"
    }
  }
}

data "aws_caller_identity" "current" {}

# Amazon Linux 2023, arm64, always current rather than a pinned AMI ID.
data "aws_ssm_parameter" "al2023_arm64" {
  name = "/aws/service/ami-amazon-linux-latest/al2023-ami-kernel-default-arm64"
}
```

The bucket is left out of the backend block and passed with `-backend-config` at init time, because it embeds the account ID. Document that in `terraform/README.md` in Task 9.

- [ ] **Step 2: Write `terraform/variables.tf`**

Variables: `region` (default `us-west-2`), `project` (default `fetzer`), `instance_type` (default `t4g.micro`), `github_repo` (default `phetzy/fetzycloudonline`), `github_ref` (default `refs/heads/main`), `ssh_port` (default `22`), and the TUI's own tunables — `idle_timeout`, `max_session`, `max_conns_per_ip`, `rate_per_min` — with defaults matching the Go program's.

Every variable gets a `description`. Any that must be positive gets a `validation` block — the Go program refuses to start on non-positive values, and catching that at plan time beats catching it in a boot loop.

### Task 3: Storage — artifact bucket and the host-key parameter

**Files:**
- Create: `terraform/storage.tf`

**Interfaces:**
- Produces: `aws_s3_bucket.artifacts`, `aws_ssm_parameter.host_key`.

- [ ] **Step 1: Write `terraform/storage.tf`**

The artifact bucket mirrors the state bucket's posture: versioned, encrypted, public access fully blocked. Add a lifecycle rule expiring noncurrent versions after 30 days — every binary is rebuildable from a commit, so there is no reason to accumulate them.

The host key is an `aws_ssm_parameter` of type `SecureString`. **The value is not set by OpenTofu.** The instance generates it on first boot and writes it. So the resource declares the parameter with a placeholder and `ignore_changes = [value]`:

```hcl
resource "aws_ssm_parameter" "host_key" {
  name  = "/${var.project}/ssh/host_key"
  type  = "SecureString"
  value = "placeholder-replaced-on-first-boot"

  # The instance generates the real key at first boot and overwrites this.
  # Without ignore_changes, every apply would revert it and change the
  # fingerprint for every returning visitor.
  lifecycle {
    ignore_changes = [value]
  }
}
```

That `ignore_changes` is load-bearing. Without it, a routine `tofu apply` silently resets the host key and every returning visitor gets a man-in-the-middle warning from their SSH client.

`tofu fmt -check && tofu validate`, then commit.

### Task 4: IAM — instance role and the GitHub OIDC role

**Files:**
- Create: `terraform/iam.tf`

**Interfaces:**
- Produces: `aws_iam_instance_profile.fetzer`, `aws_iam_role.github_deploy`.

**This is the task where a mistake is most expensive.** A wrong trust condition on the deploy role lets other repositories — or any fork's pull request — assume it.

- [ ] **Step 1: Read the existing OIDC provider with a data source**

```hcl
# Already exists in this account from earlier work. Creating a second one
# fails with EntityAlreadyExists, and destroying this config must not remove
# a provider other projects may depend on.
data "aws_iam_openid_connect_provider" "github" {
  url = "https://token.actions.githubusercontent.com"
}
```

- [ ] **Step 2: The instance role**

Trust: `ec2.amazonaws.com`. Attach `AmazonSSMManagedInstanceCore` (managed). Then one inline policy granting exactly:

- `s3:GetObject` on `${artifacts_bucket_arn}/*` — the binary
- `s3:ListBucket` on the bucket, so a missing object is a clean 404 rather than a confusing 403
- `ssm:GetParameter` and `ssm:PutParameter` on the host-key parameter ARN only
- `kms:Decrypt` and `kms:Encrypt` on the account's default SSM KMS key, needed for `SecureString`

No wildcards on resources.

- [ ] **Step 3: The GitHub deploy role**

The trust policy is the security-critical part:

```hcl
data "aws_iam_policy_document" "github_trust" {
  statement {
    effect  = "Allow"
    actions = ["sts:AssumeRoleWithWebIdentity"]

    principals {
      type        = "Federated"
      identifiers = [data.aws_iam_openid_connect_provider.github.arn]
    }

    condition {
      test     = "StringEquals"
      variable = "token.actions.githubusercontent.com:aud"
      values   = ["sts.amazonaws.com"]
    }

    # Scoped to one ref on one repository. `repo:owner/name:*` would let any
    # branch — including one pushed by a fork's pull request — assume this
    # role. StringEquals, not StringLike, so no wildcard can creep in.
    condition {
      test     = "StringEquals"
      variable = "token.actions.githubusercontent.com:sub"
      values   = ["repo:${var.github_repo}:ref:${var.github_ref}"]
    }
  }
}
```

Its permissions policy grants exactly:

- `s3:PutObject` on `${artifacts_bucket_arn}/*`
- `ssm:SendCommand` on the `AWS-RunShellScript` document **and** on the specific instance ARN — both resources are required, and granting only the document would allow commanding every instance in the account
- `ssm:GetCommandInvocation` on `*` (AWS does not support resource-level permissions for it), so the workflow can wait for the result

`tofu fmt -check && tofu validate`. Then **read the rendered trust policy back** and confirm the `sub` value is exactly `repo:phetzy/fetzycloudonline:ref:refs/heads/main`. Report it in your summary.

### Task 6: The boot script and the systemd unit

**Files:**
- Create: `terraform/user_data.sh`, `terraform/files/fetzer.service`, `terraform/files/update-fetzer.sh`

**This task has no AWS calls and is the most testable thing in the plan** — `shellcheck` and a careful read are the whole gate.

- [ ] **Step 1: Write `terraform/user_data.sh`**

Templated with `templatefile()`. It must be idempotent — `user_data` runs once per instance, but a reboot of a replaced instance runs it again.

```bash
#!/usr/bin/env bash
set -euo pipefail
```

Then, in order:

1. `dnf -y install awscli-2` if not present (AL2023 ships `aws` but do not assume).
2. Create the `fetzer` system user: `useradd --system --no-create-home --shell /usr/sbin/nologin fetzer` guarded by `id fetzer || ...`.
3. **Disable sshd:** `systemctl disable --now sshd` then `systemctl mask sshd`. Masking matters — without it a package update can re-enable it, and then the instance has two things fighting over port 22 and one of them is an admin login.
4. Fetch the host key. If `aws ssm get-parameter` returns the placeholder or fails with `ParameterNotFound`, generate `ssh-keygen -t ed25519 -N '' -f /var/lib/fetzer/host_key` and `aws ssm put-parameter --overwrite`. Otherwise write the fetched value out. `chmod 600`, owned by `fetzer`.
5. Install `update-fetzer.sh` to `/usr/local/bin/`, executable.
6. Run it once to pull the binary — tolerating "no binary published yet" as a non-fatal condition, since the first apply happens before the first deploy.
7. Install the unit, `systemctl daemon-reload`, `systemctl enable --now fetzer`.

Log everything to `/var/log/fetzer-bootstrap.log` as well as stdout, because when this fails the only way in is SSM and the cloud-init log is where the answer lives.

- [ ] **Step 2: Write `terraform/files/fetzer.service`**

```ini
[Unit]
Description=fetzer SSH TUI
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=fetzer
Group=fetzer
ExecStart=/usr/local/bin/fetzer -addr :${ssh_port} -host-key /var/lib/fetzer/host_key \
  -idle-timeout ${idle_timeout} -max-session ${max_session} \
  -max-conns-per-ip ${max_conns_per_ip} -rate-per-min ${rate_per_min}
Restart=on-failure
RestartSec=2s

AmbientCapabilities=CAP_NET_BIND_SERVICE
CapabilityBoundingSet=CAP_NET_BIND_SERVICE
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
PrivateTmp=true
PrivateDevices=true
ProtectKernelTunables=true
ProtectControlGroups=true
RestrictAddressFamilies=AF_INET AF_INET6
RestrictNamespaces=true
LockPersonality=true
MemoryMax=256M
ReadWritePaths=/var/lib/fetzer

[Install]
WantedBy=multi-user.target
```

`MemoryMax` is deliberate: the SSH library accumulates `env` requests per channel without a cap, and panic coverage is partial. Together with `Restart=on-failure`, an unbounded-growth bug becomes seconds of downtime instead of an instance-wide OOM.

- [ ] **Step 3: Write `terraform/files/update-fetzer.sh`**

Pull the current binary from S3 to a temp path, `chmod +x`, verify it runs (`fetzer -h` or equivalent exits cleanly), move it into place atomically, restart the unit. Fail loudly and leave the running binary alone if any step fails — a failed deploy must not take the service down.

- [ ] **Step 4: Verify**

```bash
shellcheck terraform/user_data.sh terraform/files/update-fetzer.sh
```

Expected: clean. Note both files contain `${...}` template placeholders that `shellcheck` may flag or misparse; if so, say exactly which warnings you suppressed and why.

### Task 8: The deploy workflow

**Files:**
- Create: `.github/workflows/deploy-ssh.yml`

- [ ] **Step 1: Write it**

```yaml
name: deploy-ssh

on:
  push:
    branches: [main]
    paths:
      - 'cmd/**'
      - 'internal/**'
      - 'content.json'
      - 'go.mod'
      - 'go.sum'
      - '.github/workflows/deploy-ssh.yml'
  workflow_dispatch:

permissions:
  contents: read
  id-token: write   # required for OIDC; nothing else needs elevating

concurrency:
  group: deploy-ssh
  cancel-in-progress: false
```

Steps: checkout; `setup-go` pinned to the repo's Go version; `go build` with `CGO_ENABLED=0 GOOS=linux GOARCH=arm64` and `-trimpath`; **`go test ./...` before shipping** — a deploy workflow that ships without running tests is a foot-gun on a public listener; `aws-actions/configure-aws-credentials@v4` with `role-to-assume` and `aws-region`; `aws s3 cp` to the SHA key and to `current`; `aws ssm send-command`; then poll `get-command-invocation` and fail the job if the command failed.

The role ARN and the bucket name are repository **variables** (`vars.`), not secrets — neither is sensitive, and putting them in `vars` keeps them visible and reviewable. Say in the README which ones to set.
